# Audit: Sprints 1–11

**Date:** 2026-11-17
**Branch audited:** `feat/sprint-11-notifications` at `bd64b15`. This includes Sprints 0–10 through the PR stack. Sprint 12 work in progress in the same folder was excluded.
**Method:** each ticked checklist item in `docs/sprints/sprint-01…11` was checked against the code, tests and CI. The audit also included a security pass over auth, authorisation, realtime and uploads, and `pnpm audit --prod`.

## Findings

| #   | Severity | Sprint | Finding                                                                                                                                                                                                                                                                                                                           | Status                                                                                                                                                                                                                                                          |
| --- | -------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | High     | 3      | OTP brute force. The 5-attempt cap was a read-modify-write counter inside the pending-OTP entry, and `POST /auth/otp/verify` had no rate limit. Many guesses sent at once all read the same count, so a 6-digit code could be brute-forced within its 5-minute life.                                                              | **Fixed.** The attempt is claimed with an atomic Redis `INCR` before the code is checked, and the budget resets with each new code. Verify is capped at 30 per IP per 10 minutes. Regression test: "parallel wrong guesses cannot exceed the 5-attempt budget". |
| 2   | High     | 3      | No server-side consent gate. `ConsentService.assertPlayAllowed` exists but nothing calls it, and the web app only has the onboarding consent page. A user who never accepted the terms, or who needs to re-accept a new version, can still create and accept challenges and submit results. F3.3 and F3.7 are ticked but not met. | **Fixed 2026-11-20** (`bd2cb83`). `PlayConsentGuard` on challenge create and accept, result and no-show submit, and DM and friend-request starts; the web app redirects `consent_required` to re-accept. Confirm, dispute and appeal stay open by design.       |
| 3   | Medium   | 11     | The notification email address is never verified. A player can set any address and the platform will email it. Volume is low because it only receives that player's own notifications, but the address is still unconsented.                                                                                                      | **Open.** Send a confirmation link and only deliver email once the address is confirmed. This fits with the F11.4 email-vendor decision.                                                                                                                        |

The 30 baseline screenshots are Windows-only (`*-win32.png`), so they can't run on the Linux runners as they stand.                                                                                                         | **Open.** Generate Linux baselines (for example in the Playwright Docker image) and add a CI job, or untick F1.7.                                                                                                                                               |
| 5   | Low      | 11     | The bottom-nav count badge used `rounded-full`, which becomes a pill at two digits. No critical findings. `pnpm audit --prod`: no known vulnerabilities. No secrets or logs are tracked by git.

## Fixed during the Sprint 11 CI work (same day)

- CORS allowed only GET/HEAD/POST, so every browser PUT, PATCH and DELETE failed, including saving notification preferences.
- Notification eligibility read `users.tos_version_accepted`, which onboarding never sets, so no real user was ever notified. It now reads `consent_records`.
- BullMQ job IDs contained `:` and were rejected, so queued push and email jobs failed.
- Badge store: a hydration mismatch, and a stale refresh overwriting a newer pushed unread count.
- Flaky relay tests (Sprints 7 and 10) and a flaky perceptual-hash test (Sprint 8).
